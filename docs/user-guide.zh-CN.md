# UvNVR 使用手册（0.12.0）

本手册覆盖从安装到完整的摄像头接入、预览、录像、回放、API/RTSP、预警和系统管理流程。

英文版本见 [`user-guide.md`](user-guide.md)。

## 1. 安装与启动

| 平台 | 安装包 | 默认数据目录 |
|---|---|---|
| Linux | `.deb`、`.rpm`、`.tar.gz` | `/var/lib/uvnvr` |
| Windows | NSIS 安装包或便携 `.zip` | `Program Files` 下运行 `%ProgramData%\UvNVR`；其他位置的便携版 `.\data` |
| macOS | `.pkg`、`.dmg`、`.zip` | `/Library/Application Support/UvNVR` |

Linux 安装包会安装并启动 systemd 服务。浏览器打开 `http://<主机>:8080`。

| 端口 | 用途 |
|---|---|
| 8080 | Web 界面与 REST API |
| 8443 | 可选 HTTPS |
| 554 | RTSP 输出（无法绑定时回退 8554/8555） |

手动运行或自定义数据目录：

```bash
uvnvr --port 8080 --rtsp-port 554 --data-dir /var/lib/uvnvr
```

端口与数据目录来自启动配置文件，无需重新构建或重装即可修改：

- Windows 安装包：NSIS 在“服务端口”页设置端口；也可以使用 x64 MSI：
  `msiexec /i uvnvr-0.7.0-windows-x64.msi HTTPPORT=8080 RTSPPORT=554`。
  NSIS 安装程序写入
  `%ProgramData%\UvNVR\uvnvr.json`，并在开始菜单生成“UvNVR Configuration”快捷方式。
- Linux：编辑 `/etc/uvnvr/uvnvr.json`，然后 `sudo systemctl restart uvnvr`。
- macOS：编辑 `/Library/Application Support/UvNVR/uvnvr.json`，然后重启 launchd 服务。
- 任意版本：使用 `--config <路径>`，或 `--port`、`--rtsp-port`、`--data-dir`。

命令行参数优先于环境变量，环境变量优先于配置文件。`uvnvr --print-config`
可查看最终生效的配置，完整格式见 [`configuration.md`](configuration.md)（英文）。

```json
{
  "http": { "port": 8080, "host": "0.0.0.0" },
  "rtsp": { "port": 554 },
  "dataDir": "/var/lib/uvnvr"
}
```

常用参数：`--version`、`--help`、`--print-config`、`--tls-self-signed`、`--maintenance`。
顶栏和登录页可在 **自动**（跟随系统）、**亮色**、**暗色** 之间切换，选择会记住。安装版在 `Program Files` 下运行时默认使用 `%ProgramData%\UvNVR`；若数据目录仍无法创建，可显式指定：

```bat
uvnvr.exe --data-dir "%ProgramData%\UvNVR"
```

服务用户、防火墙与备份见 [`deployment.md`](deployment.md)（英文）。

## 2. 首次初始化

1. 首次访问会自动跳转到设置页。
2. 设置并确认 `admin` 密码。密码使用 scrypt 加盐存储，不会写入日志。
3. 设置时区（默认取浏览器时区）。
4. 使用 `admin` 登录。

初始化完成前，其他 API 一律返回需要初始化的错误。初始化接口在成功后不能重复调用；管理员密码可在用户页修改。

## 3. 添加摄像头

打开 **通道管理**。列表显示状态、协议、主/子码流地址、最后错误、最后在线/离线时间。

### ONVIF 扫描

1. 点击 **扫描 ONVIF**，填写摄像头探测用的账号和密码。
2. 选择发现的设备。系统会调用 `GetDeviceInformation`、`GetProfiles`、`GetStreamUri`，显示厂商、型号、固件与 Profile。
3. 点击 **添加**，按所选 Profile 创建通道。

0.1.0 只探测 `http://` 的 ONVIF 设备服务。网络阻止发现时，可用协议 **ONVIF** 手动填写设备地址。

### 手动 RTSP

1. 点击 **添加通道**。
2. 选择协议：
   - **RTSP**：填写完整主码流地址，例如
     `rtsp://user:pass@192.168.1.64:554/Streaming/Channels/101`。
   - **海康**：填写 IP、端口和凭据，自动生成 `Streaming/Channels/101|102`。
   - **大华**：自动生成 `cam/realmonitor?channel=1&subtype=0|1`。
   - **通用**：使用带占位符的自定义 URL 模板。
3. 可启用子码流并填写地址。多画面预览建议使用子码流，降低 CPU 与带宽压力。
4. 可设置水印文字与位置（在浏览器预览和抓拍上叠加）。
5. ONVIF 摄像头可启用 **使用摄像头 ONVIF 事件**。UvNVR 会订阅摄像头的 PullPoint 服务，
   将移动、人形、遮挡与越线通知转换为预警。
6. 保存后通道立即开始连接。

在通道编辑中点击 **自动识别**，会按填写的 IP 依次尝试 ONVIF、海康 ISAPI、大华 CGI（HTTP Digest），
选择对应协议时会优先尝试该品牌；自动填写协议、码流地址和名称。摄像头 HTTP 不在 80 端口时，
在 **HTTP / ONVIF 端口** 中填写实际端口；
在 **扫描 ONVIF** 结果中点击 **立即添加** 可一键创建通道。识别到海康/大华时会使用内置的
主/子码流路径模板，无需手写 RTSP 地址；其他 ONVIF 摄像头使用 Profile 地址，仍可手动填写 RTSP。
通道列表显示数字 `#id` 和抓拍缩略图，摄像头按钮可刷新，双击缩略图查看大图。**重连** 可立即重试，无需等待退避。**同步** 会在显示差异后把选定字段和/或录像计划复制到其他通道。

使用 **通道分组** 将通道组织为树形结构：可创建分组并指定上级分组，在通道编辑中选择所属分组。
未分配分组的通道显示在“未分组”下。删除分组会把其中的通道移到未分组，并把子分组上移到被删分组的父级；
预览树和通道列表会立即更新。

要一次接入多台摄像头，点击 **导入 CSV** 并选择
`host,username,password,brand,name,httpPort` 格式的文件。表头可选，可通过 `host` 或 `ip`
列识别；也接受 `user`、`pass`、`http_port` 别名。`brand` 填 `hikvision` 或 `dahua`
时优先尝试对应品牌接口，留空则优先尝试 ONVIF。`name` 可覆盖识别出的名称。
每一行都会走与 **自动识别** 相同的探测流程并创建通道，按钮会显示 `已完成/总数`。
已存在相同主机的通道会被跳过，失败行会连同主机名一起列出。导入在浏览器中逐条执行，
列表较大时每台摄像头需要一轮探测时间。

### 通道状态

`disabled → connecting → online → reconnecting → offline/error`

拉流线程按带抖动的指数退避重连（1s、2s、5s、10s、30s 上限）。看门狗还会检测“连接仍在但没有数据”的情况。若摄像头无法上线，先用 VLC/ffplay 验证 RTSP 地址，再查看通道的“最后错误”。

## 4. 实时预览

打开 **实时预览**（仪表盘之后的第二页）。

1. 选择 1/4/8/16/32 画面布局，或自定义行列（各 1–8）。
2. 从左侧通道树拖入画面，或先点击通道再点击空白格；用 **清除** 清空格子。
3. 在线画面双击全屏；离线画面显示通道名和离线标识，双击进入通道管理。
4. 为整个布局选择主码流或子码流。
5. 布局可命名保存，并使用标签切换；点击 **×** 标签可删除。布局保存在服务端并绑定用户账号，
   换浏览器后仍可使用；浏览器本地保留一份缓存以便离线打开。
6. **一键播放** 会填满当前布局并启动所有画面；**一键停止** 只停止播放，不清除布局。
   通道数多于画面数时，用翻页箭头切换；**录像** 会打开所选通道的回放页。

同一摄像头只建立一路连接，所有消费者共享。每个预览客户端有独立有界队列：慢客户端会丢帧到下一个关键帧或被断开，不影响其他客户端与录像。

## 5. 录像计划

打开 **录像计划**。

1. 选择通道和录像码流（主/子）。
2. 选择画笔：**定时**、**预警**、**定时+预警** 或 **擦除**。
3. 在 7 × 48 网格（每格半小时）上拖出矩形框，可一次批量绘制多行、多格；擦除画笔可清除框选区域。
   绘制到 24:00 的计划会以结束时间 1440 正常保存。
4. 保存。使用 **同步** 复制到其他通道。

录像是计划驱动的：只有当前星期与时间落在已绘制格内才会录像。没有启用的存储卷或计划时不会产生录像。

**预警** 与 **定时+预警** 格还会按事件录像：检测到移动，或摄像头上报 ONVIF 人形、遮挡、越线事件时，
UvNVR 会从缓冲区带上预录开始一个片段，并持续录制后录；后续预警会在单段最长时长内延长该片段，
即使码流停止，也会在后录结束后收尾。可在 **系统设置 → 事件录像** 中配置总开关与时长
（默认启用，预录 10 秒、后录 30 秒、单段最长 300 秒），也可通过
`GET/PUT /api/v1/settings` 的 `event` 组设置。事件片段以 `record_type=event` 建立索引，
可像计划片段一样回放。

可在 **系统设置** 调整：

- `recording.segment_minutes`：按时间切片，默认 5 分钟。
- `recording.segment_size_mb`：按大小切片，默认 256 MB。
- 切片在超过阈值后的第一个关键帧结束。

切片为不可变的 MPEG-TS 文件并写入 SQLite 索引。写入过程中崩溃会留下 `.part` 文件，录像服务启动时修复或重建索引。

## 6. 存储管理

打开 **存储管理**。

- 添加存在且可写的路径。每个卷可配置：
  - **循环录制**：达到上限后删除最旧切片。
  - **录满预警**：达到上限后停止录像并告警。
- 可配置最大使用率（默认 90%）、保留空间与保留天数（默认 30 天；**0 表示永久保留**）。
  过期切片会自动清理。
- 禁用卷不会删除已有文件。

卷列表下方的 **当前录像** 面板每 5 秒刷新一次，显示新切片写入的存储卷，以及每个录像器
的类型（**计划** 或 **事件**）、状态、当前文件、已写字节数与切片开始时间。空闲通道显示 **空闲**，
不显示当前文件。
该面板读取内存中的录像器状态，不扫描磁盘，可用于确认数据确实在写入。

非运维模式不能手动删除视频文件。自动保留与循环清理属于策略操作，会写入审计。
运维模式下 **格式化存储卷** 会在输入卷路径确认后，删除该卷上的所有 UvNVR 录像及索引记录；
不会执行文件系统格式化，也不会删除无关文件。

## 7. 回放与下载

打开 **回放**。

1. 选择通道、码流和日期。
2. 时间轴显示有录像的区间；点击切片或时间点开始播放。
3. 回放通过 WebSocket 发送 MPEG-TS，跨切片时无需重新加载播放器。
4. 跳转会从目标时间创建新的播放票据，只读取所需切片和小窗口预读数据。点击时间轴上的录像区间即可跳转。
5. 播放器工具栏提供按时间轴窗口等比的快退快进按钮和 **0.25×–32×** 倍速。时间轴可从 24 小时
   放大到 5 分钟，跳转步长为可见窗口的 1/24（24h → 1h，1h → 2.5m）。**倒放** 按所选倍速向后步进。
   服务端按所选速率控制发送节奏；快进即高速正向播放，快退通过连续向后跳转实现
   （浏览器无法反向解码 GOP）。
6. **下载** 获取单个 MPEG-TS 切片，支持 HTTP Range 断点续传。**导出 MP4**
   使用随包 FFmpeg 将所选片段转封装为 fast-start MP4；填写 **开始/结束** 可按任意时间范围下载。
   不进行转码。码流切换会开始新切片，回放会在切换点停止，跳到下一段即可切换编码。
7. 回放与下载共享 64 KiB 块 LRU 缓存（默认 128 MB），当前切片播放时提前预读下一片。
   命中率、未命中与占用可在“系统设置”查看；可通过 `storage.cacheMb` 与
   `storage.readaheadMb` 调整。
8. 运维模式下可使用 **删除** 按钮删除所选切片的文件与索引记录；录像必须位于已配置的存储卷内。

回放与下载共享存储模块内部的 LRU 块缓存和预读层；应用层只请求索引与字节偏移。

## 8. 抓拍、API 与 RTSP 输出

### 抓拍

`GET /api/v1/channels/{id}/snapshot` 返回 JPEG，可用查询参数设置宽、高与质量。优先使用硬件解码，失败时回退 CPU。

### REST API

1. 在 **系统设置 → API Token** 创建 Token。Token 只显示一次，数据库只保存哈希。
2. 请求头使用 `Authorization: Bearer <token>`。
3. 创建 Token 时可勾选 **API 权限**：预览、抓拍、通道查询/添加/删除/管理、回放/下载、预警、计划、存储、
   时间、系统、RTSP、审计、用户。分组复选框和“全选”可一键勾选子项；不勾选则继承账户角色权限，
   且 Token 权限不会超过账户角色。完整列表见 [`api.md`](api.md)。
4. OpenAPI 3.1 文档位于 `/api/v1/openapi.json`，`http://<主机>:8080/api/docs` 提供自托管
   Swagger UI。两者都需要 `api.access`；使用 Token 调试时点击 **Authorize** 填入 Bearer Token，
   使用 Cookie 会话修改数据时需附加 `X-CSRF-Token` 请求头。

API 鉴权失败计入独立的 API 锁定策略。

### RTSP 输出

```
rtsp://user:pass@host:554/live/{channel}/{main|sub}
rtsp://user:pass@host:554/live/{channel}        # 主码流
```

RTSP 支持 Basic 与 Digest 鉴权（MD5、`qop=auth`），输出 H.264/H.265 RTP（payload type 96），支持 TCP interleaved 或 UDP unicast。需要 `rtsp.access` 权限；子码流关闭时请求子码流会返回明确错误。`DESCRIBE` 最多等待 2 秒获取流的参数集，通道离线时返回 503；当前只转发视频，音频尚未封装，RTCP SR 每 5 秒发送一次。

### 实时 WebSocket

`POST /api/v1/streams/ticket` 返回短期、单次使用的票据和 `/ws/live?ticket=...` 路径。凭据不放进 URL，避免摄像头密码进入浏览器历史或代理日志。

另一个 `/ws/events` 连接用于推送预警和通道状态变化：先调用 `POST /api/v1/events/ticket`
（需要 `alert.view`）取得票据，再连接返回的 `wsPath`。界面登录后会自动连接，
新预警会弹出提示，预警中心会就地刷新。事件票据单次使用，30 秒后过期。

## 9. 预警与邮件

打开 **预警中心**。可按级别和确认状态筛选，查看抓拍并确认（确认操作会审计）。

预警来源：

- 移动侦测：对低分辨率采样帧做帧差检测。可在 **系统设置 → 移动侦测** 启用，并配置灵敏度
  （1–100）、冷却秒数和一个百分比矩形区域。这是实验性功能，不是 AI。
- 摄像头 ONVIF 事件（移动、人形、遮挡、越线）：在通道中启用后生效，同类事件每通道 60 秒冷却。
- 摄像头离线与恢复事件。
- 存储将满事件。

在 **系统设置 → 邮件预警** 配置 SMTP。默认预置 QQ 邮箱（`smtp.qq.com:465`），需使用授权码而不是登录密码。**测试** 会立即发送一封邮件；TLS 证书校验保持开启。

## 10. 用户、角色与安全

打开 **用户与角色**。

- 用户属于某个角色。内置 admin、operator、viewer；自定义角色可逐项勾选 Web 与 API 权限。
- Web 权限覆盖仪表盘、预览、回放、下载、通道、计划、存储、预警、用户、日志、系统、运维。
- API 权限覆盖 `api.access`、`api.snapshot`、`api.stream`、`api.download`、`api.alerts`、`rtsp.access`。
- 禁用用户后，其会话在下一次请求时失效。

锁定策略默认值（均可在 **系统设置** 修改）：

| 策略 | 默认 |
|---|---|
| Web 登录失败锁定阈值 | 10 次 |
| Web 锁定时间 | 10 分钟 |
| API 失败锁定阈值 | 100 次 |
| API 锁定时间 | 10 分钟 |

锁定与解锁均写入审计。摄像头与 SMTP 密码使用 AES-256-GCM 和 `<data-dir>/secret.key`（权限 0600）加密。请将该文件与数据库一起备份；丢失后无法恢复已保存的凭据。

### 运维模式

以 `--maintenance` 启动后开放高危操作：

- 在 **回放** 中删除单个录像切片（文件与索引记录）。
- 在 **日志** 中清理审计记录，或先导出 CSV。
- 在 **系统设置** 中修改序列号或显示版本号。
- 在 **存储管理** 中格式化存储卷：删除 `<卷>/uvnvr` 下的所有 UvNVR 录像及索引记录，
  不执行 `mkfs`，也不删除无关文件；需输入卷路径确认。

这些操作要求管理员、二次确认并写入审计；非运维模式下一律返回 403。显示版本号只影响界面与
系统概览，`/healthz` 仍返回构建版本。

## 11. 系统设置

**系统设置** 包含：

- 安全：锁定阈值、审计保留天数（默认 180）、时区、界面语言。
- 时间：服务器时间、NTP 开关/服务器/偏移、立即同步、使用浏览器时间校准。页面时钟逐秒更新。
  两种同步都会设置 ONVIF 摄像头时间；海康/大华即使未开 ONVIF，也会通过 ISAPI/CGI 校时。
  结果会显示成功/失败数量；纯 RTSP 摄像头没有控制通道，会被跳过。
- 事件录像与移动侦测：预录/后录、单段最长时长，以及移动侦测的灵敏度/冷却/区域。
- 性能：自动识别的性能档位（低/中/高）与 GPU 状态。档位限制同时采样的移动侦测通道数
  （低 2、中 4、高 8）。GPU 开关让抓拍和移动侦测采样优先尝试硬件解码，失败时回退软件；
  实时预览与录像始终使用流复制。
- 运维（仅在 `--maintenance` 启动时显示）：序列号与显示版本号。
- 邮件：SMTP 主机、端口、账号、密码、发件人与测试发送。
- API Token：创建、查看、吊销。
- 日志：应用日志路径与级别；审计日志保存在 SQLite。

仪表盘显示 CPU、内存、磁盘、在线通道数、录像状态、会话、预警和码率曲线，是默认首页。

## 12. 审计日志

打开 **日志**。可按类别（认证、通道、录像、存储、API、系统、预警、权限、运维）、级别、结果、操作人、来源 IP、关键字和时间范围筛选；结果分页。
**导出 CSV** 会下载筛选结果（UTF-8 带 BOM，最多 10 万条）。运维模式下 **清理日志** 可在确认后
删除审计记录，清理操作本身也会写入审计。

审计记录到期后自动清理。

- **关于**：版本号、git 提交、序列号、构建信息、依赖与许可证、项目开源地址。

## 14. 故障排查

| 现象 | 排查 |
|---|---|
| 摄像头一直离线 | 用 VLC/ffplay 测试 RTSP 地址；检查凭据、端口与 ONVIF 权限；查看通道“最后错误”。 |
| 预览黑屏 | 改用 H.264 子码流；H.265 的 MSE 播放依赖浏览器与硬件；确认码流已启用。 |
| 没有录像 | 计划需覆盖当前星期/时间，存储卷需启用且可写，通道需在线。 |
| 无法绑定 554 | Linux 授予 `CAP_NET_BIND_SERVICE` 或以 root 运行；否则使用日志中的回退端口并更新客户端地址。 |
| 邮件测试失败 | QQ 邮箱需要授权码，并启用 STARTTLS/SMTPS；检查主机、端口与 TLS。 |
| 登录被锁定 | 等待配置的锁定时间；错误信息会显示剩余时间，事件已写入审计。 |
| 磁盘占满 | 降低保留天数、启用循环录制或增加存储卷；可用空间需高于保留阈值。 |
| H.265 RTSP 客户端无画面 | 客户端需支持 H.265 RTP（RFC 7798）；否则请使用 H.264 子码流或浏览器预览。 |

更多问题见 [`faq.md`](faq.md)。安全相关报告请遵循 [`../SECURITY.md`](../SECURITY.md)。
