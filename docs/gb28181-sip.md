# GB/T 28181 SIP stack (P6.2a)

This stage adds a self-hosted SIP user agent for the lower-device role of a
GB/T 28181 deployment: it registers with a platform, answers the Digest
challenge, refreshes the registration before it expires, sends Keepalive
heartbeats and reconnects with exponential backoff. It is deliberately
independent of the existing preview/recording/ONVIF paths.

The stack is written for libuv/libuvcpp; no eXosip2/libosip2 (GPL/LGPL) code is
used. The module is compiled only with `-DUVNVR_ENABLE_GB28181=ON` and is not
linked into the server binary yet, so the default build is unchanged.

## Build

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release \
  -DUVNVR_LIBUVCPP_ROOT=/home/zwy/.local/uvcpp-1.9.1/usr \
  -DCMAKE_PREFIX_PATH=/home/zwy/.local/uvcpp-1.9.1/usr \
  -DUVNVR_ENABLE_GB28181=ON -DUVNVR_BUILD_TESTS=ON
cmake --build build -j4
ctest --test-dir build --output-on-failure
```

| Target | Purpose |
| --- | --- |
| `uvnvr_gb28181` | static library (`src/gb28181/sip.cpp`) |

## CLI and fake registrar

`sip_reg_cli` prints every SIP message on the wire, every state transition and
every retry with millisecond timestamps. The Python registrar implements the
401 Digest challenge and enough of REGISTER/MESSAGE to exercise the client.

```sh
# terminal 1
python3 tools/sip_reg_cli/fake_sip_server.py \
  --transport udp --port 5060 --realm 3402000000 --password 12345678

# terminal 2
build/sip_reg_cli --server-host 127.0.0.1 --server-port 5060 \
  --username 34020000001320000001 --password 12345678 \
  --domain 3402000000 --server-id 34020000002000000001 \
  --keepalive 60 --expires 3600 --duration 15
```

Use `--tcp` on both sides for SIP over TCP. The registrar verifies the Digest
response, so a client-side authentication bug shows up as a repeated 401
rather than a false success.

To observe reconnect backoff, stop the registrar while the client is running,
wait for a few `state=backoff ... retry in N ms (attempt M)` lines, then start
it again. The client re-creates the socket (UDP) or the TCP connection and
registers again; a fresh server nonce is handled by one extra 401/retry.

## Behaviour

### Messages

Inbound MESSAGE requests are acknowledged with `200 OK` and then handed to
`SipUaCallbacks::on_message`; the MANSCDP answer is sent back with
`SipUserAgent::SendMessage`. The codec and the responder built on this hook are
documented in `docs/gb28181-manscdp.md`.

`SipMessage::Parse` accepts CRLF and bare LF line endings, folded header lines,
multiple Via headers, compact header forms (`v`, `f`, `t`, `i`, `m`, `l`, ...)
and a body delimited by `Content-Length`. It reports `kIncomplete` for a
truncated TCP prefix, which the TCP transport uses to split coalesced messages.
Header injection is impossible on the send path: CR/LF in names and values is
rejected or replaced, and `Content-Length` is always recomputed from the body.

Parsed/built headers cover the registration essentials: Via, From, To,
Call-ID, CSeq, Contact, Max-Forwards, Expires, User-Agent, Content-Type and
Authorization/Proxy-Authorization.

### Registration state machine

```
stopped -> connecting -> registering -> registered
                            |  ^            |
                            v  |            v
                          backoff <------ failure/timeout
```

* First REGISTER has no Authorization. A `401`/`407` with a Digest challenge is
  answered with a new transaction (new branch, incremented CSeq) carrying
  `Authorization`/`Proxy-Authorization`.
* Credentials use the GB/T 28181 convention: SIP user = 20-digit device ID,
  Digest MD5 or MD5-sess with `qop=auth`. The nonce count is maintained per
  challenge; a stale nonce gets exactly one automatic retry.
* `200 OK` reads `Expires` (falling back to `Contact;expires`, then the
  configured lifetime) and schedules a refresh at `expires - min(30 s, 10%)`.
  Refreshes reuse the cached challenge and therefore normally complete without
  a 401 round trip.
* `423 Interval Too Brief` is retried once with `Min-Expires`.
* Keepalive is a `MESSAGE` with a MANSCDP-style `<Notify><CmdType>Keepalive`
  body, `Content-Type: Application/MANSCDP+xml`, a monotonically increasing
  `SN`, and the configured device ID. The next heartbeat is scheduled from the
  send time, so the period does not drift with the response time.
* A failed registration, keepalive or transport closes the pending
  transaction and retries after
  `min(max_backoff, initial_backoff * 2^(attempt-1))`.
  `attempt` starts at 1 and resets to 0 after a successful REGISTER.
* UDP REGISTER/MESSAGE retransmissions use the same branch and CSeq with a
  500 ms doubling interval until the request timeout. TCP has no SIP
  retransmission (the transport is reliable); a timeout forces a reconnect.

### Transport

Both transports run directly on libuv handles attached to the caller's
`uvcpp_loop`; all callbacks are on the loop thread.

* UDP binds an ephemeral port, advertises it in Via/Contact, sends to the
  resolved registrar and receives datagrams from any address (response
  matching is by Call-ID/CSeq).
* TCP connects, frames messages by Content-Length, queues writes (libuv allows
  one write request per connection at a time) and treats FIN/reset/read errors
  as a transport failure.
* `local_ip` is advertised in Via/Contact. Set it explicitly for any registrar
  that is not on a directly reachable address; when it is empty the stack uses
  the numeric registrar address (correct for loopback and flat lab networks).

## Verification performed for P6.2a

The checked-in commands above were run against the local fake registrar:

* UDP and TCP: `REGISTER` -> `401 Unauthorized` -> authenticated `REGISTER` ->
  `200 OK`, followed by Keepalive `MESSAGE` -> `200 OK` every configured
  interval.
* `expires=3` with `keepalive=1`: registration refresh at ~2.5 s and heartbeat
  at ~1 s, both re-armed after every accepted request.
* Killing the TCP registrar while registered: `state=backoff
  tcp connection closed: end of file; retry in 1000 ms (attempt 1)`, then
  `tcp connect: connection refused; retry in 2000 ms (attempt 2)`, then a new
  connection and successful re-registration after the registrar returned.
* `sip_test` covers URI/address parsing (including IPv6 and invalid inputs),
  compact/folded headers, request/response parsing, stream framing, RFC 2617
  Digest vector, error handling and the backoff function.

## Not in this stage

* MANSCDP XML commands (Catalog/DeviceInfo/PTZ/Alarm) and RTP/PS media.
* Upper-platform (server) role and INVITE/BYE dialogs.
* TLS and GB 35114 signalling protection (GM/T 0024 needs Tongsuo/GmSSL).
* Digest algorithms other than MD5/MD5-sess; RFC 3261 mandates MD5 for SIP
  Digest, and that is what GB/T 28181 platforms use today.
