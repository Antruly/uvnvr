# 合规工作线：GB/T 28181 / GB 35114 / GA/T 2155.2

本文件是 UvNVR 面向国内公安与政企项目的合规设计基线。目标是把「互联互通」与
「视频信息安全」两套要求做进产品，而不是靠外挂网关。

## 0. 约束（先定边界，避免后面返工）

| 约束 | 决定 |
| --- | --- |
| 许可证 | 本仓库以 **MIT** 发布，所以**不得引入 GPL / LGPL / AGPL 依赖**（含静态链接） |
| SIP 栈 | **自研**，跑在 libuvcpp 事件循环上；不用 eXosip2/libosip2（GPL/LGPL） |
| 国密算法 | OpenSSL 3（Apache-2.0）已提供 SM2/SM3/SM4；国密 TLS（GM/T 0024）需要 Tongsuo 或 GmSSL（均为 Apache-2.0），作为可选构建 |
| 证书 | GB 35114 设备证书必须由具备资质的 CA 签发；产品侧只实现"导入 / 校验 / 使用"，不自签冒充 |
| 认证 | 证书与检测报告由检测机构（如公安部第三研究所）出具；本仓库交付的是"可送检的技术实现 + 自测证据" |

## 1. 标准拆解

### 1.1 GB/T 28181（公共安全视频监控联网系统信息传输、交换、控制技术要求）

NVR 在联网中通常担任**下级设备**（向上级平台注册并推送媒体），本设计按此实现，
后续可扩展上级平台侧。

必须实现：

- **SIP 信令**：REGISTER（含鉴权与刷新）、MESSAGE（MANSCDP）、INVITE/BYE/ACK（实时流与回放）、
  心跳（Keepalive）、注册失败重试与过期重注册。
- **MANSCDP XML**：Catalog（设备目录查询与响应）、DeviceInfo、DeviceStatus、
  RecordInfo（录像查询）、PTZCmd（云台控制）、Alarm（报警上报）、ConfigDownload（可选）。
- **国标编码**：20 位设备/通道 ID（`中心编码(8) + 行业编码(2) + 类型编码(3) + 序号(7)`），
  与本地 `channel_id` 建立映射并持久化。
- **媒体传输**：RTP 承载 **PS 封装**（GB/T 28181 附录 C），支持 UDP 与 TCP 被动/主动模式，
  SSRC 管理、时间戳、I 帧对齐、关键帧请求（PLI 对应 `RTCP` 或平台下发重新 INVITE）。
- **回放**：RecordInfo 查询本地录像索引 → INVITE 携带回放参数 → 按倍速/暂停/拖拽推流。
- **语音对讲（可选）**：音频 PS 封装。

### 1.2 GB 35114（公共安全视频监控联网信息安全技术要求）

三个安全等级，逐级增强：

- **A 级**：设备与平台双向身份认证 + 视频数据完整性（签名），不加密。
- **B 级**：A 级 + 视频数据加密（SM4），密钥经 VKEK 分发。
- **C 级**：B 级 + 信令与媒体全链路更强保护（通常配合专用密码模块）。

实现要点：

1. **证书体系**：设备证书（SM2）+ CA 链；支持导入 PFX/PEM、生成 CSR；密钥安全存储
   （Windows DPAPI / Linux 600 + 可选 TPM）。
2. **信令安全**：SIP over **国密 TLS（GM/T 0024）**，套件 `ECDHE_SM4_CBC_SM3` 等；
   依赖 Tongsuo/GmSSL，编译期开关。
3. **视频签名（A 级）**：对 I 帧（或每秒摘要）做 SM3 → SM2 签名，随流传输
   （SIP 或 RTP 扩展头/独立通道），平台侧可验。
4. **VKEK 分发**：平台下发加密的工作密钥（VKEK），设备用 SM2 私钥解出，
   再用 SM4 加密视频 ES。
5. **审计与证书状态**：证书过期告警、吊销列表（CRL）校验、失败计数与锁定。

### 1.3 GA/T 2155.2-2024（公安视频图像信息系统安全测试规范 第 2 部分：产品检测）

这是**测试方法**标准。产品侧应对应实现下列安全能力，并保留证据：

| 类别 | 要求 | 现状 |
| --- | --- | --- |
| 身份鉴别 | 唯一标识、口令复杂度、失败锁定、会话超时、双因子（可选） | 已有口令策略/锁定/会话，缺双因子 |
| 访问控制 | 最小权限、角色分离、越权防护 | 已有权限点，需补充矩阵化审计 |
| 安全审计 | 关键操作留痕、日志防篡改、留存期 | 已有审计，缺防篡改（SM3 链） |
| 数据完整性 | 配置/录像/固件完整性校验 | 缺固件签名与录像摘要 |
| 数据保密性 | 敏感数据（口令、密钥、抓图）加密存储 | 口令已哈希，缺 SM4 静态加密 |
| 通信安全 | 传输加密、抗重放 | 已有 TLS，缺国密套件 |
| 软件容错 | 异常输入、资源耗尽保护 | 部分具备，需专项测试 |
| 升级安全 | 固件签名验证、回滚保护 | 缺 |

## 2. 目标架构

```
src/
  crypto/            SM2/SM3/SM4 封装、证书与密钥管理、随机数
  secure/            审计日志链、固件签名校验、静态数据加密
  gb28181/
    sip.{h,cpp}      SIP 事务/对话/注册/心跳（libuvcpp 之上）
    manscdp.{h,cpp}  XML 编解码与命令分发
    ps.{h,cpp}       PS 封装（RTP 负载）
    rtp.{h,cpp}      RTP/RTCP 会话、SSRC、重传与关键帧请求
    device.{h,cpp}   国标 ID 映射、目录与状态机
  gb35114/
    cert.{h,cpp}     证书与 CA 链
    sign.{h,cpp}     I 帧签名/验签
    vkek.{h,cpp}     密钥分发与 SM4 流加密
    tls_gm.{h,cpp}   国密 TLS 适配（Tongsuo/GmSSL，可选）
```

设计原则：

- 现有 RTSP/ONVIF/私有协议/录像链路**不改**；GB 模块只作为新的接入与输出通道。
- 媒体复用现有 Stream（TS/ES）管线，新增 PS 封装器，不复制解码逻辑。
- 所有国密操作走 `crypto/`，便于替换后端（OpenSSL / Tongsuo / 硬件密码机）。
- 合规功能用编译开关隔离：`UVNVR_ENABLE_GB28181`、`UVNVR_ENABLE_GB35114`、
  `UVNVR_ENABLE_GM_TLS`，默认关闭，避免影响普通部署。

## 3. 阶段与验收

| 阶段 | 交付 | 验收证据 |
| --- | --- | --- |
| P6.0 | 差距矩阵 `docs/compliance-gap.md`（按 2155.2 逐条）+ 测试用例骨架 | 每条有"满足/待做/不适用"+ 代码或接口位置 |
| P6.1 | `crypto/` + `secure/`：SM2/SM3/SM4、证书导入与 CSR、审计链、固件验签、SM4 静态加密 | 单测 + 真机：改一条审计日志被检出；伪造固件被拒；SM4 录像可回放 |
| P6.2 | `gb28181/`：SIP 注册/心跳/目录/实时流/回放/云台/报警 | 与 wvp-GB28181-pro 互通全流程，附抓包与平台侧截图 |
| P6.3 | `gb35114/` A 级（签名）→ B 级（加密） | 与支持 35114 的平台联调：签名验过、加密流可解、篡改被拒 |
| P6.4 | 送检材料包：自测报告、用例、抓包、日志、架构与密钥管理说明 | 报告可直接提交检测中心 |

依赖顺序：**28181 先于 35114**——VKEK 与签名协商都跑在 SIP 信令上，没有 28181 就没有 35114 的载体。

## 4. 已知风险

1. **国密 TLS**：OpenSSL 3 只有算法，无 GM/T 0024 套件；需 Tongsuo/GmSSL，并解决 MinGW 交叉编译。
2. **PS 封装**是工作量最大的一块（时间戳、I 帧对齐、TCP 主动/被动模式差异）。
3. **证书与检测**是外部流程，周期长，需提前准备材料。
4. GA/T 2155.2 的条目以正式标准文本为准，本文件的矩阵需在拿到标准全文后逐条校对。

## 5. 与 AI 工作线的关系

AI（车牌/人脸）与合规互不阻塞：AI 事件可以后续作为 28181 的报警（Alarm）上报，
抓图与特征的静态加密复用 P6.1 的 SM4 能力。
